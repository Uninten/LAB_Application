# 接口与数据字段约定

本文档用于应用端与云平台/后端/嵌入式组员对齐数据字段。前期字段先按课设总框架设计，后续根据华为云 IoTDA 实际物模型调整。

## 0. 当前数据来源说明

当前 Web 默认不显示模拟数据，页面中的温度、湿度、烟雾、光照、门禁记录和报警记录都等待云平台接入。

临时演示时可以打开：

```text
index.html?mock=1
```

该模式只用于前期页面调试，不代表最终真实数据来源。

正式联调时，推荐不要让浏览器前端直接保存华为云 AK/SK、IAM Token 或设备密钥。更稳妥的方式是由云平台同学提供一个“后端转发服务”，Web 端只请求后端接口。

推荐最终链路：

```text
设备/开发板
  ↓ MQTT/HTTP 上报
华为云 IoTDA
  ↓ 数据转发/规则触发/后端查询
后端转发服务
  ↓ HTTP 或 WebSocket
Web 应用端
```

如果课程时间有限，也可以由后端定时查询华为云设备影子/设备属性，Web 页面每 2-5 秒轮询后端接口。

## 0.0 前端填写位置与密钥填写位置

本 Web 工程只填写后端接口地址，位置是：

```text
src/services/config.js
```

示例：

```js
window.LabConfig = {
  API_BASE_URL: "http://localhost:3000",
  WS_URL: "ws://localhost:3000/ws",
  DEVICE_ID: "Lab_Device_01",
  POLL_INTERVAL_MS: 2500
};
```

这里的 `API_BASE_URL` 是你们自己后端服务的地址，不是华为云密钥。`WS_URL` 是后端 WebSocket 地址，如果后端不做实时推送可以留空。

华为云相关密钥应该放在后端工程，例如后端 `.env` 文件：

```text
HUAWEI_CLOUD_AK=这里填云平台同学的 AK
HUAWEI_CLOUD_SK=这里填云平台同学的 SK
HUAWEI_CLOUD_PROJECT_ID=这里填项目 ID
HUAWEI_CLOUD_IOTDA_ENDPOINT=这里填 IoTDA 接口地址
IOTDA_DEVICE_ID=Lab_Device_01
```

`.env` 文件不要上传到公开仓库，也不要发给无关人员。

如果云平台同学用的是 IAM Token，也同样放后端环境变量或后端配置文件，不要放进 `api.js`、`config.js`、`index.html`。

## 0.1 到时候怎么“订阅”云平台数据

先说明一个容易混淆的点：**浏览器前端一般不直接订阅华为云 IoTDA**。

原因是华为云接口通常需要认证信息，例如 Token、AK/SK 或应用侧凭据。如果把这些信息写进前端代码，任何打开网页的人都能看到，不安全。因此更推荐：

```text
Web 页面不直接连华为云
Web 页面只连自己小组的后端服务
后端服务再去连华为云 IoTDA
```

这里说的“订阅”，实际可以理解为：**后端服务持续获取华为云里的设备数据，再把数据提供给 Web 页面**。

应用端常见有两种接入方式：

| 方式 | 说明 | 适合程度 |
|---|---|---|
| 后端轮询华为云属性，Web 轮询后端 | 后端定时调用华为云 IoTDA API 获取最新设备属性，Web 调 `/api/device/latest` | 最适合课设，简单稳定 |
| 华为云数据转发到后端，Web 用 WebSocket 接收 | IoTDA 收到设备上报后转发给后端，后端通过 WebSocket 推送给页面 | 实时性更好，但实现稍复杂 |

推荐课设采用第一种，先保证联调成功。后面如果时间充足，再升级为 WebSocket 实时推送。

应用端需要云平台同学提供：

- 华为云产品 ID、设备 ID，例如 `Lab_Device_01`。
- 物模型属性名和数据类型。
- 控制命令名和参数格式。
- 一个后端接口地址，例如 `http://localhost:3000/api/device/latest`。
- 命令下发接口，例如 `POST /api/control/fan`。
- 门禁记录和报警记录来源，是数据库记录、云平台事件，还是后端自己保存。

## 0.2 推荐给本课设的最简单接入方案

建议本课设使用“后端轮询华为云，Web 轮询后端”的方式。

### 第一步：设备端上报数据

嵌入式设备通过 MQTT 或 HTTP 把数据上报到华为云 IoTDA。上报的数据要对应物模型字段，例如：

```json
{
  "temperature": 26.5,
  "humidity": 58.2,
  "smoke": 120,
  "light": 680,
  "humanStatus": 1,
  "doorStatus": 0,
  "fanStatus": 0,
  "lightStatus": 1,
  "alarmStatus": 0,
  "rfidStatus": "合法用户"
}
```

### 第二步：云平台同学在华为云创建物模型

云平台同学需要在 IoTDA 里创建产品、设备和物模型，把这些字段定义好。

Web 端只关心字段名是否一致。例如云平台定义的是 `temperature`，页面就按 `temperature` 读取；如果定义成 `temp`，前端就需要改映射。

### 第三步：后端服务获取华为云数据

后端服务可以定时请求华为云 IoTDA 的设备属性查询接口，拿到最新属性后整理成 Web 需要的格式。

后端给 Web 提供一个简单接口：

```text
GET /api/device/latest
```

Web 页面每 2-5 秒请求一次这个接口，拿到最新数据后刷新页面。

### 第四步：Web 页面展示数据

Web 页面调用：

```js
fetch("/api/device/latest")
```

然后把返回值填到温度、湿度、烟雾、光照、设备状态等位置。

### 第五步：Web 远程控制设备

用户点击“开门”“开风扇”“解除报警”时，Web 页面不直接控制硬件，而是请求后端：

```text
POST /api/control/door
POST /api/control/fan
POST /api/control/light
POST /api/control/alarm/reset
```

请求内容示例：

```json
{
  "deviceId": "Lab_Device_01",
  "status": 1
}
```

后端收到后，再调用华为云 IoTDA 的命令下发接口，把命令发给设备。设备执行后再上报状态，Web 下一次刷新时就能看到状态变化。

### 第六步：门禁记录和报警记录

华为云设备属性通常更适合保存“最新状态”，例如当前温度、当前门锁状态。

门禁记录和报警记录属于“历史事件”，建议后端自己保存到一个简单数据库或 JSON 文件中：

- RFID 每刷一次卡，后端保存一条门禁记录。
- 发生烟雾异常、温度异常、非法刷卡时，后端保存一条报警记录。
- Web 分别调用 `/api/rfid/list` 和 `/api/alarm/list` 获取记录。

## 0.3 如果要做真正的实时推送

如果你们后期想做得更像“订阅”，可以让后端使用 WebSocket。

流程如下：

```text
设备上报数据
  ↓
华为云 IoTDA
  ↓ 数据转发到后端，或后端通过 AMQP/MQTT 订阅
后端收到新数据
  ↓ WebSocket 推送
浏览器页面立即刷新
```

这种方式的优点是实时性好，不需要页面一直轮询。缺点是后端代码更复杂，课程设计前期不建议一开始就做。

## 0.4 应用端同学真正要写什么

你负责 Web 应用端时，重点不是直接研究华为云的全部订阅细节，而是把接口边界定义清楚：

```text
我需要一个接口拿实时状态
我需要一个接口拿历史曲线
我需要一个接口拿门禁记录
我需要一个接口拿报警记录
我需要一个接口下发控制命令
```

对应到当前代码，就是改 `src/services/api.js`：

```js
async function getStatus() {
  const response = await fetch("/api/device/latest");
  return response.json();
}
```

页面其它代码不需要知道数据到底来自华为云、数据库还是 MQTT。

## 1. 设备属性字段

| 字段名 | 类型 | 含义 | 示例值 | Web 显示方式 |
|---|---|---|---|---|
| `temperature` | number | 温度 | `26.5` | 温度卡片、温度曲线 |
| `humidity` | number | 湿度 | `58.2` | 湿度卡片、湿度曲线 |
| `smoke` | number | 烟雾浓度 | `120` | 烟雾卡片、烟雾曲线、报警判断 |
| `light` | number | 光照强度 | `680` | 光照卡片、光照曲线 |
| `humanStatus` | number | 是否有人 | `0`/`1` | 无人/有人 |
| `doorStatus` | number | 门锁状态 | `0`/`1` | 关闭/开启 |
| `fanStatus` | number | 风扇状态 | `0`/`1` | 关闭/开启 |
| `lightStatus` | number | 灯光状态 | `0`/`1` | 关闭/开启 |
| `alarmStatus` | number | 报警状态 | `0`/`1` | 正常/报警中 |
| `rfidStatus` | string | RFID 识别状态 | `合法用户` | 门禁状态、门禁记录 |

## 2. 状态值约定

| 字段 | 值 | 含义 |
|---|---:|---|
| `humanStatus` | `0` | 无人 |
| `humanStatus` | `1` | 有人 |
| `doorStatus` | `0` | 门锁关闭 |
| `doorStatus` | `1` | 门锁开启 |
| `fanStatus` | `0` | 风扇关闭 |
| `fanStatus` | `1` | 风扇开启 |
| `lightStatus` | `0` | 灯光关闭 |
| `lightStatus` | `1` | 灯光开启 |
| `alarmStatus` | `0` | 正常 |
| `alarmStatus` | `1` | 报警中 |

## 3. 控制命令约定

| 命令名 | 功能 | 参数建议 | Web 入口 |
|---|---|---|---|
| `openDoor` | 远程开门 | 无或 `{ "value": 1 }` | 开门按钮 |
| `closeDoor` | 远程关门 | 无或 `{ "value": 0 }` | 关门按钮 |
| `openFan` | 打开风扇 | 无或 `{ "value": 1 }` | 开风扇按钮 |
| `closeFan` | 关闭风扇 | 无或 `{ "value": 0 }` | 关风扇按钮 |
| `openLight` | 打开灯光 | 无或 `{ "value": 1 }` | 开灯按钮 |
| `closeLight` | 关闭灯光 | 无或 `{ "value": 0 }` | 关灯按钮 |
| `resetAlarm` | 解除报警 | 无或 `{ "value": 0 }` | 解除报警按钮 |

## 4. Web 需要的接口

### 4.1 获取实时状态

```text
GET /api/device/latest
```

返回示例：

```json
{
  "deviceId": "Lab_Device_01",
  "online": true,
  "updatedAt": "2026-05-13 16:30:00",
  "properties": {
    "temperature": 26.5,
    "humidity": 58.2,
    "smoke": 120,
    "light": 680,
    "humanStatus": 1,
    "doorStatus": 0,
    "fanStatus": 0,
    "lightStatus": 1,
    "alarmStatus": 0,
    "rfidStatus": "合法用户"
  }
}
```

### 4.2 下发控制命令

```text
POST /api/control/fan
```

请求示例：

```json
{
  "deviceId": "Lab_Device_01",
  "status": 1
}
```

返回示例：

```json
{
  "success": true,
  "message": "命令已下发"
}
```

### 4.3 获取历史曲线数据

```text
GET /api/device/history?range=5m
```

返回示例：

```json
[
  {
    "time": "16:30:00",
    "temperature": 26.5,
    "humidity": 58.2,
    "smoke": 120,
    "light": 680
  }
]
```

### 4.4 获取门禁记录

```text
GET /api/rfid/list
```

返回示例：

```json
[
  {
    "time": "2026-05-13 16:30:00",
    "cardId": "A1B2C3D4",
    "person": "学生卡",
    "result": "允许进入",
    "doorAction": "开门"
  }
]
```

### 4.5 获取报警记录

```text
GET /api/alarm/list
```

返回示例：

```json
[
  {
    "time": "2026-05-13 16:31:20",
    "type": "烟雾异常",
    "level": "严重",
    "value": "smoke=850",
    "status": "未处理"
  }
]
```

## 5. 前期 mock 数据建议

前期没有真实设备时，Web 可以每隔 2 秒随机生成一组数据：

- 温度：`20-35`
- 湿度：`35-80`
- 烟雾浓度：`80-900`
- 光照强度：`100-1000`
- 报警状态：当烟雾浓度超过阈值或温度过高时置为报警

这样可以提前完成页面效果、曲线刷新和报警展示，等硬件和云平台完成后再替换数据来源。
